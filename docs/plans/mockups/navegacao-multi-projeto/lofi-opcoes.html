Navegação multi-projeto

Três direções em baixa fidelidade para as duas dores de hoje. Tudo em cinza de propósito: nesta etapa decidimos estrutura, não visual. O azul marca o que muda em cada opção.

OBJETIVO 1 · EDITORTrocar de tarefa sem "voltar"

Do editor, pular para outra tarefa — mesmo de outro projeto — sem refazer o caminho quadro → dropdown → procurar.

OBJETIVO 2 · QUADROVer o estúdio inteiro

Tarefas de todos os projetos visíveis de uma vez, cada uma com dono claro — e "sua vez" nunca escondida atrás de um dropdown.

legenda: ● trabalhando ◐ sua vez ○ concluída projetos: L leapy-web · B backoffice · S site-inst

  • 1Trilho substitui o menu do topo — projetos com tarefas aninhadas, sempre à mão. Início/Experiência/Configurações moram no rodapé do trilho.
  • 2O glifo de cada tarefa dá o estado do estúdio inteiro de relance — "sua vez" nunca some, em nenhuma tela.
  • 3Clicar no projeto foca o quadro nele; clicar numa tarefa abre o editor direto.
  • 4No editor o trilho encolhe para ícones (não rouba espaço do chat + preview); a bolinha no projeto avisa quando algo pede você.
  • 5Passar o mouse expande: as tarefas do projeto aparecem ali — trocar é 1 clique, sem sair do editor.

Prós

  • Navegação e estado permanentes, iguais em todas as telas.
  • Troca de tarefa a 1 clique de qualquer lugar.
  • Escala bem para o futuro agente que abre tasks: o trilho vira o mapa do estúdio.

Contras

  • A maior obra das três — appbar → trilho muda todas as telas.
  • Disputa largura com chat + preview (mitigado pelo modo ícones).
  • Com muitos projetos/tarefas o trilho pede busca e colapso.

Contras

  • Abas pedem gestão: abrir/fechar, limite, o que acontece ao concluir/arquivar.
  • Colunas apertam com 4+ projetos (scroll horizontal).
  • Duas superfícies novas para aprender (abas + colunas).

Dá para combinar

  • O ⌘K (B·6) cabe em qualquer direção — vale ter mesmo escolhendo A ou C.
  • O quadro agrupado por projeto (B) pode ser o modo "Todos" dentro da direção A.
  • As abas (C) funcionam sobre o quadro de hoje, sem as colunas — dá para adotar metade da direção.
PERGUNTA 1

Quantos projetos ficam vivos ao mesmo tempo? 2–3 → B ou C · 4+ → A

PERGUNTA 2

Você troca de tarefa o tempo todo (babá do paralelo → A ou C) ou pontualmente, quando algo pede você (→ B)?

PERGUNTA 3

Prefere algo sempre visível na tela (→ A ou C) ou resolve no teclado com ⌘K (→ B)?

Baixa fidelidade de propósito — direção primeiro, visual depois. Escolhida a direção, a alta fidelidade segue o design system atual (Onest, accent monocromático, borda-primeiro).
